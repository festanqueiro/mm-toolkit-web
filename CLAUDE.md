# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

A fully client-side browser port of the desktop app [festanqueiro/mm-toolkit](https://github.com/festanqueiro/mm-toolkit) (PySide6 + FFmpeg), checked out locally at `../record-label-mediatools`. **No media processing may ever happen server-side**: the deployment is static files only.

The repo is currently **specs-first**. Before implementing anything, read `docs/specs/README.md` and the spec for the area you're touching. Specs carry exact user-facing strings, defaults and algorithms; keep them unless a spec documents a deviation. When behaviour is ambiguous, `docs/reference/desktop-source/` (desktop v1.0.2, commit `a0c8576`) is the oracle. If you change behaviour, update the spec in the same PR.

## Architecture rules (see docs/specs/01-architecture.md)

- `src/engine/` is pure TypeScript with no main-thread DOM APIs. It runs inside Workers and is the only layer that needs exhaustive unit tests. This mirrors the desktop's `core.py` vs `ui/` split.
- **Never run long media work on the main thread.** Every job goes through `workers/job.worker.ts` with typed progress/succeeded/failed/cancelled messages.
- Route codecs by **runtime capability detection** (`engine/media/capabilities.ts`), never by user-agent.
- Stream decode → effect → encode → mux → sink. Never buffer all frames. Process batches sequentially.
- Cancel and failure must delete partial outputs (every `OutputSink` implements `remove`).
- A worker entry module must statically import nothing (see `workers/job.worker.ts` → `job-host.ts`): if a lazy chunk imports shared code back from the entry, WebKit evaluates the entry a second time, duplicating Mediabunny (registered WASM encoders vanish) and `onmessage` (Cancel is lost). `e2e/build.spec.ts` guards it.
- Never `terminate()` a worker that may hold a WebGPU device: WebKit crashes the page. The Stem Splitter reuses one worker; cancel is cooperative.
- UI colours come from theme tokens that follow `prefers-color-scheme`. No hardcoded colours in components.

## Parity gotchas (easy to get wrong)

- Python `round` is **banker's rounding**: `formatTimestamp(0.5) → 00:00:00`, `1.5 → 00:00:02`. Don't use `Math.round`.
- Python `-w // 8` is `floor(-w / 8)`, not `-floor(w / 8)`.
- Desktop frames are RGB, but `effects.py` names `cv2.split` results `b, g, r`. VHS shifts **R left / B right**; Glitch's "red split" shifts **blue**.
- Filters run in **float64** at the file's **native sample rate**.
- Envelope window is `floor(sampleRate / fps)` (it drifts slightly; replicate it).
- Rotate angle is `-(t * rpm / 120) * 360`. The /120 and the negation are intentional.
- Tracks shorter than ~28 s propose a drop near the end. It's a known quirk; keep it for parity.

## Commands

```bash
npm install && npx playwright install
npm run dev                                   # dev server
npm run lint && npm run check                 # ESLint + svelte-check (types)
npm test                                      # Vitest in Node (unit + golden parity)
npm run test:gl                               # WebGL parity in real browsers (Vitest browser mode)
npx vitest run tests/pure.test.ts -t parseTimestamp   # single test
npm run test:e2e                              # Playwright: chromium, webkit, firefox
npx playwright test --project=chromium        # one engine
npm run build                                 # GITHUB_PAGES=1 for the /mm-toolkit-web/ base
```

Stack: Vite 8, Svelte 5 (runes), TypeScript 6 (pinned: svelte-check doesn't support 7 yet), Vitest, Playwright. Hosted on GitHub Pages: no custom headers, so the CSP is a meta tag injected at build time and ffmpeg.wasm will run single-threaded (spec 13).

## Golden fixtures

`fixtures/golden/` is generated by `scripts/generate_golden.py` from the real desktop engine. Never hand-edit it. Regenerate with:

```bash
MM_TOOLKIT_DESKTOP=../record-label-mediatools ../record-label-mediatools/.venv/bin/python scripts/generate_golden.py
```

## Commit messages

Use [Conventional Commits](https://www.conventionalcommits.org/): `<type>: <description>`, e.g. `feat: port drop detection to TypeScript`, `fix: use banker's rounding in formatTimestamp`. Types: `feat`, `fix`, `docs`, `refactor`, `test`, `chore`, `ci`, `build`. Imperative, under ~72 chars.

## Versioning & release flow

- `package.json#version` is the single source of truth (injected into About and the PWA cache name). Starts at `0.1.0`; `1.0.0` = desktop feature parity.
- Every merge to `main` is a release and bumps **patch** by default. **Minor** or **major** only when the user explicitly asks for it for that release.
- `main` is the only long-lived branch. Work on short-lived `feature/*` / `fix/*` / `chore/*` branches and PR into `main`.
- PR descriptions need a real body (Summary + Test plan).
